# Decision tests

Use only the tests that illuminate this choice.

- **Feasibility:** Which necessary step lacks time, skills, authority, or a dependency? What smaller version removes it?
- **Demand or evidence:** What behavior supports the promised benefit? What would contradict it? A competitor's existence or a friend's enthusiasm is not proof of demand.
- **Incentives:** Who must behave differently, and why would they? Include friction and misuse where they affect the proposal.
- **Cost:** Include the user's time, coordination, switching, and upkeep. Use supplied values or labelled estimates; do not manufacture a market price.
- **Reversibility:** What can be tested before a large commitment? Name the sunk cost or exit condition only when meaningful.
- **Recovery:** If the likely failure occurs, can the user recover without losing the core objective?

A useful recommendation often looks like: "Proceed with the smaller version. The main assumption is X. Test it with Y before spending Z; change direction if the observed result is below the agreed threshold." Thresholds can be proposed choices; label them that way rather than as evidence-backed universal benchmarks.
