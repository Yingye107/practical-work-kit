# Technical or complex handoffs

Add only the fields necessary to resume this project safely:

- The actual repository or artifact location, relevant branch/commit or file identity when accessible, and uncommitted work that affects the task.
- The authority for requirements and decisions: accessible documents or exact necessary user statements. Preserve conditions and exclusions.
- Checks actually run, results, version and environment, and known failures or checks not run. Historical reports stay historical.
- The minimum files and sections to read next. Avoid copying volatile facts into several competing ledgers.
- The next requested action and any unresolved condition that affects it.

If several supplied snapshots disagree, identify which artifact or current user instruction resolves the disagreement. Do not choose "latest" by filename, discard normal history, or claim a stale test verifies changed code. If evidence is unavailable, mark the affected detail unknown while preserving independent useful context.

Use an existing project's handoff conventions when requested. Avoid adding a mandatory tracker, naming system, or parallel source of truth. Ask before overwriting an unrelated or ambiguous existing artifact. A concise new snapshot is preferable when it preserves provenance without modifying prior records.

For cross-device or cross-tool continuation, include necessary safe excerpts or deliver the referenced files. Local filesystem paths and process handles are pointers, not portable access or restored runtime state.
